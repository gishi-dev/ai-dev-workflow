# 差分レビューの観点

AIが書いた差分を、AI自身と人がレビューするときの観点です。
1回で終わらせず、修正した部分も含めて、指摘がなくなるまで繰り返します。

## 正しさ

- Issueの受け入れ条件を、すべて満たしているか。
- 対になる処理（保存と読み込み、作成と削除、送信と取り消しなど）の片方だけを直していないか。同じ種類の抜けが、ほかの経路に残っていないか。
- 「今はこう動いている」という前提を、コードや実行結果で確かめたか。
- 例外やエラーのときに、途中までの処理が残って不整合にならないか。

## 事故の防止

- 二重送信・二重登録が起きないか。複数のタブや再送で同時に届くリクエストも考えたか（「利用者が1人だから同時には来ない」は根拠にならない）。
- 本番のDBや外部サービスに、意図せずつながる経路がないか。
- 認証情報・Cookie・個人情報を、ログ・画面・エラーメッセージ・コミットに出していないか。
- 許可されていない外部送信を、自動化していないか。

## テスト

- 追加・変更したテストは、修正を元に戻すと失敗するか（戻しても通るテストは何も守っていない）。
- 既存テストを、理由なく削除・弱体化していないか。弱める場合は、何を守っていたテストかを確かめたか。

## 読みやすさ

- コメントが実装と一致しているか。削除したコメントにあった制約や判断が、読み取れなくなっていないか。
- 今回の目的に不要な抽象化・共通化を足していないか。

## 手動での確認

- 途中の状態を手で作らず、実際の入口（画面・コマンド）から通して確かめたか。
- 前回の確認で残ったデータが、今回の確認結果に紛れ込んでいないか。
